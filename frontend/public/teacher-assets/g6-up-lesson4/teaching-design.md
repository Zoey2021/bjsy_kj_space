# 浙教版（2023）六年级上册《第4课 算法的程序体验》教学设计（公开课）

---

## 一、教学内容梳理

### 1.1 课题位置

| 项目 | 内容 |
|------|------|
| 教材版本 | 浙江教育出版社（2023版） |
| 年级 | 六年级上册 |
| 单元 | 第一单元《算法的实现》 |
| 课题 | 第4课 算法的程序体验 |
| 课时 | 1课时（35分钟） |
| 教学环境 | 计算机教室（每生一机）+ IDLE / 在线Python环境 |

**前后衔接**：
- 前接：第3课《算法设计》——学生已画出鸡兔同笼的枚举法流程图（开始→ji=0→循环判断→计算→条件判断→输出→ji+1→回）
- 本课：把流程图**翻译成代码**。核心新知：Python基础语句（赋值、循环、条件、输出）+ IDLE环境操作
- 后启：第5课《验证算法》——运行并调试程序，用多组数据测试正确性

### 1.2 教材核心内容

#### 知识点

1. **算法的程序描述**——同一个算法可用不同语言（Python、C等）描述，算法是思想，程序是实现
2. **程序运行环境**——Python IDLE：Shell窗口（交互式，逐行运行）+ 编辑器窗口（写完整程序）
3. **Python基础语句**：
   - 赋值语句：`=`（给变量赋值）
   - 输出语句：`print()`（向屏幕输出结果）
   - 条件循环：`while 条件:`（条件为真时重复执行）
   - 单分支条件：`if 条件:`（条件为真时执行）
   - 比较运算符：`==`、`<`、`>`、`!=`
4. **Python语法规则**：冒号`:`表示代码块开始、4空格缩进表示层级

## 二、教学目标

- **信息意识**：能说出常见程序设计语言（Python、C）的名称和用途；理解算法是思想、程序是思想的语言表达
- **计算思维**：能将枚举法流程图**逐框对应翻译**成Python代码；理解流程图中的判断框变`if`/`while`、处理框变赋值语句、输出框变`print()`
- **数字化学习与创新**：能独立打开IDLE编写和运行简单Python程序；能根据报错信息定位并修改代码错误
- **信息社会责任**：在使用IDLE时遵守机房规范；理解代码是知识产权的一部分

---

## 三、学情分析与教学策略

### 3.1 六年级学生的真实起点

| | 学生会 | 学生不会 |
|------|--------|----------|
| 鸡兔同笼 | 第2课建好模型，第3课画好流程图 | 不会把流程图的框变成代码 |
| 编程 | 零基础（绝大多数没写过代码） | Python语法规则、英文单词拼写、缩进格式 |
| 打字 | 会拼音输入法，英文打字较慢 | 快速准确输入英文代码 |
| 第3课流程图 | 笔记本上有完整的枚举法流程图 | 看不懂`while`、`if`、`print`对应哪些框 |

### 3.2 公开课四大设计原则

1. **流程图到代码，逐框翻译**——学生手里有第3课画的流程图，教师带着学生一框一框地对应写代码。流程图上的每个框都是代码中的一行或一个结构。学生不是凭空写代码，而是在**翻译**。
2. **先Shell再编辑器**——先在Shell中逐行试（即时反馈，不怕错），感受Python的交互性；再用编辑器写完整程序（保存、运行），体验完整流程
3. **错误是最好的老师**——故意让学生看到报错（如忘记冒号、缩进不对），然后引导学生读报错信息、修改——这比"一次写对"的教学效果好得多
4. **板书是"流程图↔代码对照表"**——一清二楚地展示每个流程图符号对应的Python语句

## 四、五环节教学过程设计

### 环节一：激趣导入——"流程图你已经画好了，今天让它'活'起来！"（约3分钟）

**环节目的**：激活第3课的流程图记忆，建立"代码就是让流程图动起来"的期待。

---

**教师活动**：

**1. 回顾流程图（约1.5分钟）**

> PPT展示第3课最后的鸡兔同笼枚举法流程图：
>
> "上节课你画了这张图——谁还记得这个框是什么意思？"（指着判断框 ji≤35?）
>
> 快速回顾：开始→ji=0→判断ji≤35→否结束，是→tu=35-ji→判断2ji+4tu=94→否ji+1回，是→输出

> "这张图画在纸上，终究是死的。今天我们要让它**'活'起来**——让计算机照着这张图自动算出鸡和兔各有几只。"

**2. 揭示课题 + 调动期待（约1.5分钟）**

> PPT展示课题：**第4课 算法的程序体验**
>
> "算法是思想，程序是思想的'翻译'。就像你可以用中文、英文说同一句话——算法也可以用不同的语言来写。"
>
> PPT出示同一个算法用三种方式表达：
> - 第3课的表达：**流程图**（图形化）
> - 今天的表达：**Python代码**（文字化）
> - 如果有时间还可以看：**C语言代码**（对比）
>
> "今天我们要学的语言叫 Python。它是最适合初学者的语言——语法接近英语自然语言，就像在跟计算机说人话。"

**3. 出示学习路径（约1分钟）**

```
今天四步走：
  ① Python是什么？—— 跟计算机说话的语言
  ② 认识Python环境 —— IDLE怎么用
  ③ 认识四句话 —— 赋值、循环、判断、输出
  ④ 把流程图翻译成代码并运行！
```

**学生活动**：
- 回忆第3课的流程图
- 建立"算法=思想，程序=语言"的认知
- 看到三步学习路径

> **设计意图**：前3课学生一直在"纸上谈兵"（画表、画图），第4课是他们第一次真正碰代码、让计算机干活。导入环节要把这个"从纸上到屏幕上"的仪式感做出来。

---

### 环节二：新知讲解——"认识Python和它的四句'人话'"（约11分钟）

**环节目的**：用最短时间讲清"Python是什么→IDLE操作→四句核心语句"。不讲语法细节——只教"流程图上的这个东西，在Python里怎么写"。

---

#### Step 0：认识Python——"跟计算机说话的语言"（约1分钟）

**教师活动**：

> "你跟同桌说话用什么语言？"→ 中文
> "你跟英国小朋友说话用什么？"→ 英语
> "你跟计算机`说话`用什么？"→ 代码、编程
>
> "对——Python就是跟计算机说话的一种`语言`。就像英语有单词和语法，Python也有自己的'单词'和'语法'。"
>
> PPT快速闪过：🧮算数学题 → 🎮小游戏 → 📊画图表 → 🤖AI
> "今天我们从第一个开始——让Python帮你算鸡兔同笼。"
>
> **学生活动**：
> - 建立"Python是跟计算机说话的语言"的认知

---

#### Step 1：认识IDLE（约1分钟）

**教师活动**（全程投影，学生跟着操作）：

> "双击桌面上的 IDLE 图标——"

教师演示，学生跟做：

1. 打开IDLE → **Shell窗口**（`>>>` 提示符）
2. 试一行：`>>> 3 + 5` → 回车 → `8`
3. `File → New File` → 空白编辑器
4. 输入 `print("Hello!")` → `File → Save` → `hello.py` → `F5运行` → Shell显示 `Hello!`

> "Shell写一行答一行，编辑器写完整程序再运行。"

**学生活动**：
- 打开IDLE，在Shell中试验 `2*3+4`
- 在编辑器中写 `print("你的名字")`，保存运行

---

#### Step 2：认识四句话——"流程图到代码的对照翻译"（约6分钟）

**教师活动**（全程板书/PPT展示对照表，一边画流程图符号一边写对应代码）：

> PPT并列展示：左边是第3课的流程图，右边是空白，准备逐行写代码

**第1句：赋值语句 `=`**

指着流程图中的处理框 `ji = 0`：

> "流程图上写 ji=0——Python里怎么写？一模一样：`ji = 0`"
>
> "`=` 叫'赋值号'——把右边的东西'装进'左边的变量里。"

板书对照表第一行：

| 流程图元素 | Python代码 |
|-----------|-----------|
| 处理框 `ji=0` | `ji = 0` |
| 处理框 `tu=35-ji` | `tu = 35 - ji` |

**第2句：条件循环 `while`**

指着流程图中的菱形判断框 `ji ≤ 35?` + 回线：

> "这个框和回线——'ji不超过35就继续循环'。Python里用 `while`。"

板书：

| 流程图元素 | Python代码 |
|-----------|-----------|
| 判断+回线 `ji≤35?` | `while ji <= 35:` |

> "注意：①末尾加冒号 `:` ②下一行缩进4格（Tab）③缩进里的代码就是'循环体'"

在编辑器中演示：

```python
ji = 1
while ji <= 5:
    print(ji)
    ji = ji + 1
```

运行 → 输出1 2 3 4 5。

**故意制造错误**（约30秒）：把冒号删掉运行 → 报错 `SyntaxError`。

**第3句：单分支条件 `if`**

指着流程图中的菱形 `2×ji+4×tu = 94?`：

> "判断总脚数是不是等于94——是就输出。Python里用 `if`。"

板书：

| 流程图元素 | Python代码 |
|-----------|-----------|
| 判断 `2×ji+4×tu=94?` | `if 2*ji + 4*tu == 94:` |

> "注意：`==` 两个等号才是'等于吗？'的问句。一个等号 `=` 是赋值。"

**第4句：输出语句 `print()`**

指着流程图中的输出框 `输出 ji, tu`：

> "输出框 → `print()`。括号里写你要输出的东西。"

板书：

| 流程图元素 | Python代码 |
|-----------|-----------|
| 输出框 `输出 ji, tu` | `print("鸡:", ji, "只，兔:", tu, "只")` |

> "引号里的内容原样显示，没有引号的变量显示它的值。"

**四句话总结（PPT归纳）**：

```
Python初学四句话：
  📦 赋值：变量 = 值        （把东西装进变量）
  🔁 循环：while 条件:      （条件真就反复做）
  ❓ 判断：if 条件:          （条件真就做一次）
  📢 输出：print(内容)       （把结果亮出来）
  
  规则：冒号: → 换行缩进4格
```

**学生活动**：
- 在Shell中逐句试写四句话
- 在编辑器中写出完整的循环示例（1到5），保存运行
- 故意犯错看报错信息，学会读 `SyntaxError` 和 `IndentationError`

---

#### Step 3：对照翻译——从流程图到完整代码（约3分钟）

**教师活动**：

> "现在回到我们的鸡兔同笼——把流程图上的每一个框，一个一个翻译成代码。"

PPT/板书逐框对照（左流程图→右代码，逐行显现）：

```
流程图                          Python代码
══════                          ══════════
「开始」                                       
  ↓                             ji = 0
ji = 0                          while ji <= 35:
  ↓                                 tu = 35 - ji
ji ≤ 35? ←──────┐                   if 2*ji + 4*tu == 94:
  ↓ 是          │                       print("鸡:", ji, "只，兔:", tu, "只")
tu = 35 - ji    │                   ji = ji + 1
  ↓             │
2ji+4tu=94? ─否─┘→ ji = ji + 1
  ↓ 是
输出 ji, tu
  ↓
「结束」
```

教师逐行在学生编辑器中打出完整代码（学生照着敲）：

```python
ji = 0
while ji <= 35:
    tu = 35 - ji
    if 2 * ji + 4 * tu == 94:
        print("鸡:", ji, "只，兔:", tu, "只")
    ji = ji + 1
```

> "保存 → 按F5运行 → 看！计算机说：鸡23只，兔12只。"
>
> "你们的流程图活了！"

**学生活动**：
- 对照自己的流程图，在编辑器中敲出鸡兔同笼枚举法代码（约2分钟）
- 保存、运行、看到结果的那一刻——"我写出了人生第一个程序！"

> **设计意图**：环节二是全课的主体。不按"先讲语法再写代码"的传统路线，而是先用1分钟回答"Python是什么"（消除零基础恐惧），再用"流程图到代码的逐框翻译"策略——学生手里有流程图，每个框都能找到Python的对应写法。四句话的讲解顺序刻意设计为"赋值→while→if→print"，刚好覆盖鸡兔同笼程序所需的全部语法。故意制造错误（忘冒号、缩进不对）让学生学会读报错，比一万遍"别忘了冒号"都有用。

---

### 环节三：探究活动——你改几个数字，再跑一次（约12分钟）

**环节目的**：趁学生刚完成"人生第一个程序"的兴奋，马上给两道变式题——让他们感受到"只改数字不改结构"的代码复用快感。

---

#### 探究一：农场鸡兔——只改三个数字（约5分钟）

**教师出示题目**：

> "刚才你写的是35头94脚。现在农场有20头56脚——把你的代码改三个数字，再跑一次。"

**不给任何提示**——让学生自己找哪三个数字要改。

**教师巡回，观察典型问题**：

| 现象 | 回应 |
|------|------|
| 不知道改哪里 | "看你的流程图——第3课农场版的判断条件是什么？代码里哪里对应这个判断条件？" |
| 改了数字但报错 | "缩进还在吗？和你原来的代码对比一下缩进。" |
| 跑完了但输出不对 | "while的条件改了吗？如果只改了循环体内的数字，循环可能跑不到正确位置。" |

**核对**（约1分钟）：修改的地方是 `while ji <= 20:`、`tu = 20 - ji`、`if 2*ji + 4*tu == 56:`。运行结果：鸡12只、兔8只。

> "看到了吗？你只改了三个数字，代码结构完全不变——程序就是这么好改。以后你遇到任何鸡兔同笼，只改数字就行。"

---

#### 探究二：百钱买百鸡——从一层循环到两层循环（约7分钟）

**教师激情引入**：

> "第3课我们说过，百钱买百鸡需要两层循环。上节课你们画了嵌套流程图，今天把它变成代码！"

**出示百钱买百鸡模型（第2课成果）**：

```
gong + mu + xiao = 100
5×gong + 3×mu + xiao/3 = 100
```

**分步引导**：

**Step 1：回顾枚举范围和判断条件（约1分钟）**
> "枚举对象？范围？" → 公鸡0~20，母鸡0~33，小鸡自动算
> "判断条件？" → 总价=100 且 小鸡能被3整除

**Step 2：出示半成品代码框架（约1分钟）**

教师在PPT上出示半成品，关键位置留空让学生填：

```python
gong = 0
while gong <= ___ :          # ① 填空
    mu = 0
    while mu <= ___ :        # ② 填空
        xiao = ___ - gong - mu   # ③ 填空
        if 5*___ + 3*___ + ___/3 == 100:  # ④⑤⑥ 填空
            print("公鸡:", gong, "母鸡:", mu, "小鸡:", xiao)
        mu = mu + 1
    gong = gong + 1
```

**Step 3：学生独立填空并运行（约3分钟）**

学生填：
- ① `20`（gong≤20）
- ② `33`（mu≤33）
- ③ `100`（xiao的公式）
- ④ `gong`、⑤ `mu`、⑥ `xiao`

**Step 4：教师揭示完整代码 + 运行演示（约2分钟）**

教师运行完整代码，屏幕显示四组解。

> "现在回过头来比较——鸡兔同笼的代码和百钱买百鸡的代码，结构上有什么相同？"

学生发现：都是 `while` 循环套 `if` 判断。区别只有：百钱买百鸡多了一层 `while`（嵌套）。

**Step 5："能不能加一层优化？"（约1分钟，可选）**

> "公鸡最多20只——但20只是怎么来的？"

引导：`5×gong ≤ 100`，所以 `gong ≤ 20`。如果公鸡的价格变了，范围也会变。这就是第5课要学的——**让程序更聪明**。

**学生活动**：
- 探究一：独立修改鸡兔代码的三个数字，运行验证
- 探究二：填空补全百钱买百鸡代码，观察嵌套循环的运行结果，体会"一层套一层"

> **设计意图**：探究一的关键是"只改数字，不改结构"——让学生感受代码的复用性，建立"流程图不变，代码结构就不变"的认知。探究二的半成品框架策略是降低门槛——第一次接触嵌套循环，从头写会卡住，但填空就容易得多。用填空的方式还能让学生集中注意力在"哪里和鸡兔不同"这个核心问题上。

---

### 环节四：反思提升——从流程图到代码，你学会了一种通用方法（约4分钟）

**环节目的**：把"流程图→代码"的对照翻译法升华为可迁移的通用技能；建立编程信心。

---

#### 活动1：流程图→代码对照表（约2分钟）

**教师活动**：

> "今天我们只学了Python——但将来你可能学C、Java、JavaScript。它们语法不同，但翻译方法一样。"

板书（或PPT）展示通用对照表：

```
流程图符号          →    任何编程语言

处理框（矩形）       →    赋值语句 / 计算语句
判断框（菱形）       →    if / switch / 条件语句
判断+回线（循环）    →    while / for / 循环语句
输出框（平行四边形）  →    print / cout / 输出函数
```

> "以后不管什么语言——你先画流程图，再查这门语言的'翻译表'，一行一行翻过去——程序就写出来了。这就是我们三节课串起来的大道理：**

```
第2课（抽象建模）→  想清楚问题
第3课（算法设计）→  画清楚流程        →  程序员的三部曲
第4课（程序体验）→  写成代码跑起来
```

#### 活动2：常见报错速查（约1分钟）

PPT展示本课最常见的两个报错及对策：

```
SyntaxError: invalid syntax
→ 忘了冒号 : ？检查 if / while 后面有没有 :

IndentationError: unexpected indent
→ 缩进不对！检查 while 或 if 下面的代码是不是对齐了
```

#### 活动3：编程初体验——写给自己的一句话（约1分钟）

**教师活动**：

> "到目前为止，你只会写一种程序——枚举法。但Python能做很多事。试试这个——"

教师在PPT上展示：

```python
name = input("你叫什么名字？")
print(name + "，恭喜你！你写出人生第一个Python程序！")
```

学生输入运行 → 看到自己的名字出现在屏幕上。

> "这个程序只有两行。但它包含了输入、处理、输出——所有程序的三个核心环节。"

**学生活动**：
- 齐读"程序员三部曲"
- 运行 `input`+`print` 小程序，输入自己名字
- 记住两个常见报错

> **设计意图**：活动1把"流程图→代码"的翻译法升级为**跨语言通用能力**——学生以后学任何语言都用得上。活动2是实用工具——学生回家自己写代码时最常遇到的就是语法错误和缩进错误。活动3是情感收尾——学生终于在屏幕上看到自己的名字和计算机的回应——这种"我能控制计算机"的成就感，是信息科技课最宝贵的东西。

## 六、公开课特别备忘

| 关注点 | 本课做法 |
|--------|----------|
| **与教材一致性** | 严格遵循教材三步：算法程序描述→运行环境→基础语句+鸡兔程序 |
| **与前3课衔接** | 开场直接用第3课流程图→对照翻译→第2课模型→百钱百鸡代码；结尾用"程序员三部曲"串联 |
| **学生动手频率** | 教师每讲一句（赋值/while/if/print），学生就在Shell中试一句；探究一独立改数字运行；探究二填空运行。全课代码实战≥12分钟 |
| **机房条件适配** | 每讲完一句代码给学生30秒～1分钟在IDLE中敲一遍；讲快的学生可以试下一步，讲慢的有教师巡回一对一指导 |
| **薄弱学生支持** | 鸡兔完整代码投在屏幕左侧不关，随时可以对照；百钱买百鸡用填空而非从零写；巡回时帮不会切换中英文输入法的学生；**环节二新增"认识Python"环节**——用"跟计算机说话的语言"类比消除零基础恐惧 |
| **错误处理** | 故意两次引发报错（忘冒号、缩进错）并现场修改，把"看报错"变成一个学习环节，防止学生回家自己做时遇到报错就放弃 |
| **情感目标** | 结尾的 `input+print` 小程序让学生看到自己名字出现在屏幕上——这是信息科技课的"哇"时刻 |
| **时间控制（35分钟版）** | 环节一3min+环节二11min+环节三12min+环节四4min+环节五5min=35min。每个环节严格计时，环节二Step 0和Step 1各压缩到1分钟，环节四去掉冗长的跨语言扩展讨论 |

> **依据课标**：《义务教育信息科技课程标准（2022年版）》第三学段"身边的算法"——"使用简单算法，利用计算机实现问题的自动化求解"。本课是单元项目"鸡兔同笼"的第四步（也是最后一步）——"算法的程序体验"，通过"流程图→代码对照翻译"策略，帮助六年级学生完成从算法思维到编程实践的完整闭环。
