# 浙教版（2023）六年级上册《第2课 抽象与建模》教学设计（公开课）

---

## 一、教学内容梳理

### 1.1 课题位置

| 项目 | 内容 |
|------|------|
| 教材版本 | 浙江教育出版社（2023版） |
| 年级 | 六年级上册 |
| 单元 | 第一单元《算法的实现》 |
| 课题 | 第2课 抽象与建模 |
| 课时 | 1课时（40分钟） |
| 教学环境 | 计算机教室 + 一体机投影 + 学生纸笔 |

**教材结构**：问题描述 → 抽象（用表格整理对象、数量、关系）→ 建模（列算式/方程）

**前后衔接**：
- 前接：第1课《算法与问题解决》——学生已知"用算法解决问题"的三步框架（抽象建模→设计算法→验证算法），初步接触了变量和流程图
- 本课：聚焦第一步"抽象与建模"，学会用表格工具对问题做结构化分析
- 后启：第3课《设计算法》——基于本课建好的模型，设计流程图算法来求解

### 1.2 教材核心内容

#### 知识点

1. **问题描述**——解决问题前，用清晰的语言描述已知条件和求解目标
2. **抽象**——从问题中提取**对象、数量、关系**三个关键要素，借助表格进行整理
3. **建模**——根据抽象的表格数据，用算式/方程建立计算模型
4. **模型通用化**——用变量代替具体数值，让模型适用于更多同类问题

#### 教材案例

| 案例 | 用途 |
|------|------|
| 鸡兔同笼（35头94脚） | 新知讲解核心案例 |
| 试一试：变量替换具体数值 | 模型通用化 |
| 百钱买百鸡（课后作业） | 迁移应用 |

## 二、教学目标

- **信息意识**：能说出问题描述、抽象、建模三个概念的含义；理解在编程解决问题前先做抽象建模的必要性
- **计算思维**：能从"对象、数量、关系"三个角度完成对问题的抽象；能借助表格整理信息；能根据表格数据列出计算模型（算式/方程）
- **数字化学习与创新**：能借助表格工具对陌生问题进行结构化分析；能与同伴协作，互相补充遗漏的抽象要素
- **信息社会责任**：在讨论模型通用化时，理解"模型不等于现实，但模型能帮我们高效解决问题"

---

## 三、学情分析与教学策略

### 3.1 六年级学生的真实起点

| | 学生会 | 学生不会 |
|------|--------|----------|
| 鸡兔同笼 | 四年级"数学广角"学过假设法、抬脚法；部分学生能口算 | 从不曾用**表格**来整理鸡兔同笼的信息 |
| 方程 | 五年级学过简易方程，能用字母表示数 | 不习惯在"信息科技课"上列方程 |
| 抽象/建模 | 零概念 | 听到这两个词就紧张 |
| 信息科技课的期待 | 想碰电脑、想写代码、想做"和数学不一样的事" | — |

### 3.2 公开课三大设计原则

1. **教材为纲，绝不偏离**——严格遵循教材的"问题描述→抽象→建模"三步结构，案例用鸡兔同笼，拓展用百钱买百鸡。评课专家看到的每一步都能在教材中找到对应。
2. **学生动手，全程可视**——每个环节学生都在画表格、填表格、查表格。评课者走进教室，看到的是全班低头写写画画、同桌互相检查的场面，而非教师一讲到底。
3. **信息科技味要足**——反复强调"表格是程序员的工具""先画表，再写代码"。环节四用30秒Python演示"模型建好了，计算机一秒解出"，让学生亲眼看到从表格到程序的完整链条。

## 四、五环节教学过程设计

### 环节一：激趣导入——"鸡兔同笼，你四年级就会算了，对吧？"（约4分钟）

**环节目的**：用"你四年级就会"制造轻松开场，紧接着提出"但你从没用表格画过它"——制造认知缺口，引出本课主题。

---

**教师活动**：

**1. 轻松暖场（约1分钟）**

> PPT展示鸡兔同笼原文："今有雉兔同笼，上有三十五头，下有九十四足，问雉兔各几何？"
>
> "这道题，四年级数学广角学过——谁还记得答案？"

学生举手：鸡23只，兔12只。追问一两个学生："你还记得当时用的什么方法吗？"

> "抬脚法、假设法——你们四年级就会了。今天信息科技课再拿出来，不是要你再算一遍——而是要你学一种**全新的方式来看这道题**。"

**2. 揭示课题（约1分钟）**

> PPT展示本课标题：**第2课 抽象与建模**
>
> "听这个名字——抽象、建模——是不是觉得特高深、特难？"
>
> "今天上完课你就知道，抽象就是你画一张表，建模就是你把表里的东西写成算式——就这么简单。"

**3. 出示学习路径（约2分钟）**

PPT展示本课三步学习路径（三个方框从左到右，当前第一步高亮）：

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│ ① 问题描述 │ → │ ② 抽象     │ → │ ③ 建模     │
│           │    │ 对象·数量·关系│    │ 列算式/方程 │
│           │    │   用表格整理  │    │           │
└──────────┘    └──────────┘    └──────────┘
```

> "今天我们就用鸡兔同笼，把这三步走一遍。走完你会发现——这三步能用来解决好多你以前觉得'没法算'的问题。"

**学生活动**：
- 回忆鸡兔同笼的答案（启动已有知识）
- 听教师拆解"抽象""建模"的通俗含义（消除畏难）
- 看学习路径图，知道今天要学什么

> **设计意图**：公开课的开场忌讳"出其不意"，而应该让学生和评课者都清楚"这堂课要干什么"。用"你四年级就会"建立自信，用"但你从没用表格画过"制造缺口，用三步路径图预告全程——3分钟内完成"暖场+揭题+预告"。

---

### 环节二：新知讲解——走一遍"描述→抽象→建模"（约14分钟）

**环节目的**：以鸡兔同笼为唯一案例，教师带着学生完整走一遍"①问题描述 → ②抽象（画表格）→ ③建模（列算式）"，每一步都是学生在笔记本上跟着写、跟着画。**这是全班第一次画表格——教师的速度要放到最慢，每一步都等全班跟上了再往下走。**

---

#### Step 1：问题描述——"先别算，先说清楚"（约2分钟）

**教师活动**：

> "解决问题之前，第一步永远是——把问题**说清楚**。就像你要给一个从没见过鸡和兔的人解释这道题。"

板书（/PPT逐行显示）：

```
问题描述：
  对象：鸡、兔
  已知：一共35个头、94只脚
        每只鸡1头2脚，每只兔1头4脚
  求：鸡几只？兔几只？
```

> "这叫问题描述——用最清楚的话，把'有什么、知道什么、求什么'一条条写下来。程序员的第一个习惯：**先描述，再动手。**"

**学生活动**：
- 在笔记本上写下鸡兔同笼的问题描述（约1分钟）

---

#### Step 2：抽象——"用一张表格把问题的关键信息抓出来"（约8分钟）

**教师活动**：

**引子（约1分钟）**：

> "问题描述好了，现在做第二步——**抽象**。"
>
> "什么叫抽象？就是：从一大堆信息里，**只看我们关心的、对解题有用的东西**。不关心的，全部扔掉。"
>
> 举个生活例子："你去食堂打饭——你关心阿姨叫什么名字吗？不关心。你关心的是：今天有什么菜、多少钱、排了多少人。这就是抽象——只关心关键信息。"
>
> "那鸡兔同笼这道题，什么信息是关键？三个角度：**对象、数量、关系。**"
>
> "我们用一个工具来整理——**表格。**"

**逐问逐填，表格在板书/PPT上一行行"长出来"（约5分钟）**：

| 教师问 | 学生答 | 板书/PPT填入 |
|--------|--------|-------------|
| "对象是谁？" | 鸡、兔 | 第一列：对象 |
| "每只鸡有什么关键属性？" | 1个头、2只脚 | 第二列：每只头数 / 第三列：每只脚数 |
| "每只兔呢？" | 1个头、4只脚 | 同上 |
| "各有几只？" | 不知道！ | **"不知道的就用字母代替——鸡设 ji 只，兔设 tu 只"** |
| "ji 只鸡，一共几个头？几只脚？" | ji个头、2×ji只脚 | 关系列：头数 = 1×ji，脚数 = 2×ji |
| "tu 只兔呢？" | tu个头、4×tu只脚 | 关系列：头数 = 1×tu，脚数 = 4×tu |
| "头一共多少？脚一共多少？" | 35、94 | 合计行 |

**完成表格**（PPT投影最终版）：

| 对象 | 每只头数 | 每只脚数 | 只数 | 总头数 | 总脚数 |
|------|:------:|:------:|:----:|:------:|:------:|
| 鸡 | 1 | 2 | ji | ji | 2×ji |
| 兔 | 1 | 4 | tu | tu | 4×tu |
| **合计** | — | — | — | **35** | **94** |

**关键小结（约2分钟）**：

> "看这张表——对象、数量、关系，一目了然。从散乱的信息到整整齐齐的表格——这就是**抽象**。"
>
> 在板书"② 抽象"旁边写下关键词：**对象 · 数量 · 关系 → 表格**

> "如果鸡和兔的颜色、年龄、公母——这些信息，我们关心吗？不关心。扔掉。只留下对解题有用的——这就是抽象。"

**学生活动**：
- 跟着教师的节奏，一步一步在笔记本上画出完整表格（约5分钟）
- 同桌交换检查：表头写对了吗？合计行填对了吗？

---

#### Step 3：建模——"从表格的合计行，直接读出算式"（约4分钟）

**教师活动**：

**1. 指着合计行，引导学生读方程（约2分钟）**：

> "表格画好了，现在做第三步——**建模**。建模就是把表格里的关系，写成数学算式。"
>
> "看合计行的'总头数'列——所有鸡的头 + 所有兔的头 = 35，写成算式是什么？"

学生：`ji + tu = 35`

> "看合计行的'总脚数'列——写成算式是什么？"

学生：`2×ji + 4×tu = 94`

**2. 揭晓这就是"模型"（约1分钟）**：

> "这两个算式——`ji + tu = 35`，`2×ji + 4×tu = 94`——就是这道题的**计算模型**。"
>
> "有了这个模型，求解就有方向了。解出来：ji = 23，tu = 12。和你们四年级算的一样——但这次，你不是靠'抬脚法'蒙出来的，而是**一张表 + 两个方程，清清楚楚推导出来的**。"

**3. 课堂第一个"试一试"——模型通用化（约1分钟）**：

> "教材上有个'试一试'：如果头数和脚数不是35和94——能不能把这个模型改一下，让它通用于所有鸡兔同笼问题？"

引导学生：把35换成字母 `t`（总头数），把94换成字母 `f`（总脚数）。

> 通用模型：`ji + tu = t`，`2×ji + 4×tu = f`
>
> "看到了吗？不管头数脚数怎么变，这个模型结构不变。这就是建模的威力——**建一次，反复用。**"

**学生活动**：
- 从自己的表格中读出两个方程并写在合计行下方
- 尝试"通用化"——用字母替换具体数字

> **设计意图**：环节二是全课的主体，严格遵循教材的"描述→抽象→建模"三步。每一步都有明确的学生动作（写描述、画表格、读方程），评课者可以清楚看到学生的学习发生过程。"通用化"这一步呼应了教材"试一试"栏目，也为环节四的迁移做了铺垫。全程用日常语言解释抽象和建模，不给学生背定义的压力。

---

### 环节三：探究活动——你自己来一遍！（约12分钟）

**环节目的**：学完方法立刻练，两道题难度递进。第一题和例题结构相同（模仿巩固），第二题需要自己从头抽象（迁移创造）。

---

#### 探究一：农场版鸡兔同笼（约5分钟）

**教师出示题目**：

> "农场里有鸡和兔，一共20个头、56只脚。请完整地做一遍——①描述、②画表、③建模——写在笔记本上。"

**PPT展示三步检查清单**：

```
□ ① 问题描述：写了对象、已知、求吗？
□ ② 抽象：表格画了吗？表头清楚吗？合计行填了吗？
□ ③ 建模：从合计行读出方程了吗？
```

**教师巡堂策略**（公开课注意）：

- 不追问"答案对不对"（都能算对），而是追问"表呢？"
- 发现跳步直接写方程的，轻拍肩膀："方程对的——但你的表格呢？评委要看的是表格哦。"
- 发现表头不清楚的："旁边同学看得懂你的表吗？加个表头。"
- 选取两份（一份标准、一份有典型小问题）用手机拍照，准备环节四投影对比

**核对答案**（约1分钟）：

标准表格 + 方程：`ji + tu = 20`，`2×ji + 4×tu = 56` → 鸡12只、兔8只

---

#### 探究二：百钱买百鸡（约7分钟）

**教师激情引入**：

> "教材课后作业有这道题——我国古代数学家张丘建在《算经》里提出了一个问题。今天我们来挑战一下！"

**PPT展示**：

> 公鸡一只5文钱，母鸡一只3文钱，小鸡三只1文钱。
> 用100文钱买100只鸡。
> 问：公鸡、母鸡、小鸡各几只？

**分步引导（不给答案，只问方向）**：

**第1步——问题描述（约1分钟）**：

> "先别解，先说清楚。对象有哪些？已知什么？求什么？"

学生写：对象（公鸡、母鸡、小鸡）、已知（100文、100只）、求（各几只？）

**第2步——抽象画表（约3分钟）**：

> "拿出表格——自己定表头。给你2分钟，和同桌讨论：表头应该写哪几列？"

学生讨论并画表。教师巡回，观察典型思路：

| 思路 | 教师回应 |
|------|----------|
| 表头写对了（只数、单价、总价）| "继续填——未知量用字母" |
| 小鸡的"三只1文"不知怎么处理 | "一只小鸡多少钱？三分之一文——但你可以换一种写法，不用分数" |
| 不知道用几个字母 | "几个未知量就用几个字母——这道题三个未知" |

**参考表格**：

| 对象 | 单价（文/只） | 只数 | 总价（文） |
|------|:----------:|:----:|:--------:|
| 公鸡 | 5 | gong | 5×gong |
| 母鸡 | 3 | mu | 3×mu |
| 小鸡 | 1/3 | xiao | xiao÷3 |
| **合计** | — | **100** | **100** |

**第3步——建模（约2分钟）**：

> "从合计行读方程："

学生得到：`gong + mu + xiao = 100`，`5×gong + 3×mu + xiao÷3 = 100`

**第4步——"求解？今天不求解"（约1分钟）**：

> "这个方程比你刚才解的鸡兔同笼复杂——三个未知数，两个方程，怎么解？"
>
> "下一节课我们学'设计算法'，就是要让计算机来帮我们试出所有可能的答案。今天你只需要——**把表画清楚。表不清，代码就没法写。**"

**学生活动**：
- 独立完成探究一（鸡兔变式）→ 同桌互查
- 合作完成探究二（百钱百鸡）→ 小组讨论表头设计 → 画完整表格

> **设计意图**：探究一是"依葫芦画瓢"的巩固，探究二是"自己造瓢"的迁移。百钱买百鸡题是教材指定课后作业，放在课堂上做提升了课堂挑战度，也展示了方法的通用性。特意在探究二结尾留悬念"今天不求解"——为第3课《设计算法》做铺垫。两道题难度分明，评课者可以看到学生在同一节课内从"模仿"到"创造"的成长。

---

### 环节四：反思提升——抽象与建模，原来是这个意思（约6分钟）

**环节目的**：把环节二、三的体验升华为概念认知；通过Python演示建立"表格→代码"的直观联系。

---

#### 活动1：对照教材，总结三步（约2分钟）

**教师活动**：

> "现在回头看看——这节课我们做了什么？"

板书回顾（指着三步路径图）：

```
① 问题描述 — 说清楚对象、已知、求
② 抽象 — 画表格，整理对象、数量、关系
③ 建模 — 从表格的合计行，读出方程/算式
```

> "抽象——把问题中关键的信息抓出来、整整齐齐放进表格。不重要的全扔掉。"
>
> "建模——用等式表达表格中的关系。`ji + tu = 35` 就是一个模型。"
>
> "这两件事，是所有程序员写代码之前必做的功课。"

---

#### 活动2：两张表格对比——点评学生作品（约1.5分钟）

**教师活动**：

> 用手机投屏刚才巡堂时拍的两份学生表格（一份标准、一份有小问题）

提问全班：
- "这两张表——你觉得哪张更好？为什么？"
- "这张表的表头清楚吗？别人看得懂吗？"

> "记住：表格不只是给你自己看的——以后你是要写给程序员的、写给计算机的。表头不清楚，别人就没法用。所以——**表头一定要写清楚。**"

---

#### 活动3：🔥 Python演示——"模型建好了，计算机一秒出答案"（约1.5分钟）

**教师活动**：

> 打开 Python 环境，展示一段极简代码（投屏）：

```python
ji = 1
while ji <= 35:
    tu = 35 - ji
    if 2 * ji + 4 * tu == 94:
        print("鸡:", ji, "只，兔:", tu, "只")
    ji = ji + 1
```

> 回车运行 → 屏幕输出："鸡: 23 只，兔: 12 只"
>
> "看到了吗？你画表建了模型，计算机就能帮你算。这就是为什么信息科技课要学抽象建模——**模型建好了，求解只是计算机的体力活。**"
>
> "下节课，我们就来学怎么写这样的程序——把今天的表格变成代码。"

**学生活动**：
- 跟着板书回顾三步
- 对比两张学生表格，说出优缺点
- 看Python演示，"哇"的瞬间——"原来信息科技课学的就是这个！"

> **设计意图**：三个活动各有分工——活动1是认知闭环（把体验概念化），活动2是同伴互评（培养工程规范意识），活动3是公开课收尾的"亮点"。Python演示只有30秒，但对六年级学生来说冲击极大——它回答了"信息科技课为什么学这个"的根本问题。评课者也能看到这个设计中的"计算思维"闭环。

### 环节五：反馈评价（约4分钟）

**环节目的**：当堂检测概念掌握，巩固"表格是核心工具"的认知。

#### 1. 口答选择题（约2分钟）

PPT逐题出示：

**Q1**：在计算机科学中，"抽象"是指：
- A. 把问题变得更复杂
- B. **抓住问题的关键信息，忽略不重要的细节**
- C. 用各种颜色标记步骤
- D. 在问题中加入许多细节

**Q2**："建模"是指：
- A. 制作一个真实大小的模型
- B. 用不同字体排版文字
- C. **把抽象出的数据和关系，用算式表达出来**
- D. 画一幅画

**Q3**：抽象建模时，我们用什么工具来整理信息？
- A. 思维导图
- B. **表格**
- C. 日记本
- D. 手机备忘录

每题全班举手作答，快速统计正确率。

## 六、公开课特别备忘

| 关注点 | 本课做法 |
|--------|----------|
| **与教材一致性** | 严格遵循教材"问题描述→抽象→建模"三步，用鸡兔同笼为核心案例，探究二用教材课后作业"百钱买百鸡" |
| **学生动手频率** | 环节二（跟画表格）、环节三探究一（独立画表）、环节三探究二（合作设计表头），全课学生动笔时间≥15分钟 |
| **信息科技味** | 表格定位为"程序员的工具"；环节四Python演示建立"表格→代码"闭环；反复强调"先画表，再写代码" |
| **可观察的学习证据** | 笔记本上的问题描述、表格、方程；举手作答的选择题；自评勾选表 |
| **差异化支持** | 探究一独立完成，探究二同桌合作；巡堂时发现薄弱学生轻声提示表头模板；探究二不强求解，降低门槛 |
| **时间控制** | 环节二14分钟最紧张——教师填表不拖堂，学生每步只给30秒写，写完即往下走；探究二7分钟如有超时倾向可砍掉通用化讨论 |
| **过渡语** | 每环节结束都有明确小结句——"好，这就是××。接下来我们……" |

> **依据课标**：《义务教育信息科技课程标准（2022年版）》第三学段"身边的算法"——"能用符号和编码表示问题求解所关心的对象"。本课以鸡兔同笼和百钱买百鸡为案例，通过"问题描述→表格抽象→算式建模"三步骤，帮助六年级学生掌握结构化抽象和数学建模的系统方法。
