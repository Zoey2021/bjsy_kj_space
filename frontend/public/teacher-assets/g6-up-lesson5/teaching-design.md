# 浙教版（2023）六年级上册信息科技 第5课《算法的执行》教学设计

## 一、教学内容梳理

### 课题位置
- **单元**：第一单元《算法的实现》
- **位置**：第5课（单元第5/6课）
- **前后衔接**：
  - 承接第2-4课：第2课建立鸡兔同笼模型（表格+方程），第3课设计枚举法算法（流程图），第4课写出Python代码（程序体验）
  - 开启第5课：将第4课写好的代码**真正运行起来**，经历"运行→调试→完善"的完整工程闭环
  - 为后续学习"猜数字游戏"等自主设计项目做准备

### 核心内容
- **知识点**：
  - 计算机通过运行程序完成对算法的执行
  - Python中运行程序的方法（IDLE中Open → Run Module）
  - 程序调试：读懂报错信息、定位语法错误
  - 完善算法：用变量记录状态（有解/无解）、增加用户输入使程序通用化
- **技能点**：
  - 在IDLE中打开和运行Python程序
  - 识别并修正四种常见语法错误（缺少冒号、缩进错误、大小写混淆、中英文标点）
  - 修改代码中的参数并观察运行结果
  - 用"变量跟踪法"完善算法（jie变量记录是否有解）
  - 用input()函数让程序接受用户输入

### 学情分析
- **学生已有基础**：
  - 已完成第4课，写过鸡兔同笼的Python代码，认识赋值、while、if、print四句话
  - 会用IDLE打开新文件、写代码、保存运行
  - 对鸡兔同笼问题的数学逻辑和枚举法原理有理解
- **本课可能难点**：
  - 报错信息是英文的，学生看到"SyntaxError"会紧张
  - 中英文标点肉眼难以区分（中文括号（）vs 英文括号()）
  - 缩进错误最隐蔽——看起来对齐了，其实是空格和Tab混用
  - "完善算法"不是修bug，而是从"特定问题"到"通用问题"的思维跃迁

## 二、教学目标

- **信息意识**：理解"计算机通过运行程序完成算法执行"的含义，认识到同一算法可以用不同语言实现，体会程序运行结果对算法验证的重要性。
- **计算思维**：能读懂Python常见的四种报错信息并定位错误；能运用"变量跟踪法"（jie变量）完善算法，使程序能处理"无解"情况；能将固定数值改为变量，提升程序通用性。
- **数字化学习与创新**：能在IDLE中独立运行、调试、修改Python程序；能根据调试结果提出算法改进方案；能在小组中分享调试经验和完善创想。
- **信息社会责任**：在调试过程中养成"先读报错再动手改"的规范习惯；认识到好的算法应能解决"一类问题"而非"一个问题"；理解程序工程化思维（写代码只是第一步，运行调试完善才是完整过程）。

## 三、学情与策略

### 核心策略："三阶段递进"——从"能跑"到"能修"到"能优化"

本课是前4课学习成果的"工程化落地"课。学生手里有代码，但代码能否跑、跑了是否正确、能不能做得更好——这是本课要回答的三个问题。教学策略围绕"三阶段递进"展开：

1. **第一阶段：运行（Run）**——"让代码活起来"（约5分钟）
2. **第二阶段：调试（Debug）**——"读懂计算机的'抱怨'"（约10分钟）
3. **第三阶段：完善（Optimize）**——"从'能用'到'好用'"（约12分钟）

### 难点突破
- **调试恐惧**：学生在第4课就可能遇到过报错，但当时教师在身边，学生不害怕。本课刻意展示3个典型错误程序，让学生集体"找茬"——把调试从"可怕的事"变成"寻宝游戏"。
- **中英文标点**：用PPT放大对比展示（中文括号 vs 英文括号），用颜色标注差异。
- **缩进可视化**：用"显示空白字符"或制作"缩进标尺"，让学生看到空格和Tab的区别。
- **通用化思维**：用"如果题目数字变了怎么办？"引导学生从"改代码里的数字"到"让程序自己问用户"的思维跃迁。

## 四、五环节教学过程

### 环节一：激趣导入——"你的代码能跑吗？"（约3分钟）

**环节目的**：制造"代码写好≠问题解决"的认知冲突，引出"运行、调试、完善"的必要性。

**教师活动**：
1. 开场："上节课我们写了鸡兔同笼的Python代码，写完了——问题解决了吗？"
2. 停顿，等待学生反应（学生通常会说"没有，还没运行"）。
3. PPT展示：左侧是写好的代码截图，右侧是空白的结果窗口，中间一个大问号。
4. "写代码只是第一步。就像你写了一封信，不寄出去对方收不到。代码不运行，计算机根本不知道你要它做什么。"
5. 亮课题："今天学习——第5课：算法的执行。三件事：运行程序、调试程序、完善算法。"
6. PPT展示今日学习路径：
   ```
   写代码（第4课） → 运行程序 → 调试程序 → 完善算法 → 通用程序
   ```

**学生活动**：
- 回忆自己第4课写的代码，意识到"还没真正跑过"
- 产生"我的代码能跑吗？"的好奇和一丝紧张

**关键提问**：
- "你写的代码，如果直接运行，会发生什么？"
- "如果运行时报错了，你会怎么办？"

### 环节二：新知讲解——"三阶段递进：运行→调试→完善"（约13分钟）

**环节目的**：分三阶段系统学习运行程序、调试程序、完善算法的方法，每个阶段有具体案例和操作。

---

#### Step 1：运行程序——"让代码活起来"（约3分钟）

**教师活动**：
1. PPT展示IDLE操作四步（快速回顾，因为第4课已学过）：
   - ① 打开IDLE → ② File → Open → 选择.py文件 → ③ Run → Run Module → ④ 看Shell窗口结果
2. 现场演示：打开一个正确的鸡兔同笼程序（35头94脚），运行，展示结果：
   ```
   鸡: 23 只
   兔: 12 只
   ```
3. 强调："运行程序 = 让计算机执行你写的算法。算法是'思路'，程序是'指令'，运行就是'执行指令'。"
4. 板书：运行程序 → 得到结果

**学生活动**：
- 在IDLE中打开自己第4课保存的鸡兔同笼程序（或教师提供的正确版本）
- 点击Run → Run Module，观察Shell窗口输出

**关键提问**：
- "你看到的运行结果和你心里算的答案一致吗？"
- "如果结果不对，问题可能出在哪里？"（代码写错了 / 算法设计错了）

---

#### Step 2：调试程序——"读懂计算机的'抱怨'"（约5分钟）

**教师活动**：
1. 过渡："程序写错了，计算机不会'自己修'——它会'报错'。报错信息就是计算机在告诉你：'这里我不懂，请改一下。'"
2. 出示三个"有bug"的程序（PPT展示代码），让学生当"找茬小侦探"：

   **Bug 程序1：大小写错误**
   ```python
   Tu = 0          # 大写T
   while tu <= 35: # 小写tu
       ...
   ```
   - 报错：`NameError: name 'tu' is not defined`
   - 分析："Tu"和"tu"是两个不同的名字！Python严格区分大小写。
   - 修正：统一变量名，全部用小写`tu`

   **Bug 程序2：中文标点错误**
   ```python
   if 2*ji + 4*tu == 94：  # 中文冒号
       print("鸡:", ji, "只")  # 中文括号
   ```
   - 报错：`SyntaxError: invalid character in identifier`
   - 分析：Python只认识英文半角标点！中文冒号、中文括号都是"外星人"。
   - PPT放大对比：中文冒号"：" vs 英文冒号":"，中文括号"（）" vs 英文括号"()"
   - 修正：换成英文标点

   **Bug 程序3：缺少缩进**
   ```python
   while ji <= 35:
   tu = 35 - ji      # 没有缩进！
       if 2*ji + 4*tu == 94:
       print("鸡:", ji, "只")  # 没有缩进！
   ```
   - 报错：`IndentationError: expected an indented block`
   - 分析：冒号后面的代码必须缩进！缩进是Python的"层级密码"。
   - 修正：在`while`和`if`的冒号后，下一行代码前面加4个空格（或按Tab）

3. 总结调试四步法（PPT展示）：
   ```
   ① 看报错类型（NameError / SyntaxError / IndentationError）
   ② 看报错行号（提示你第几行出错）
   ③ 对照四错清单（大小写？标点？冒号？缩进？）
   ④ 修改后重新运行
   ```

**学生活动**：
- 三人小组各领一个Bug程序（或每人依次尝试），根据报错信息定位错误
- 在IDLE中修改后重新运行，验证是否修复

**关键提问**：
- "报错信息里的行号有什么用？"（精准定位）
- "NameError、SyntaxError、IndentationError，分别对应哪类错误？"
- "如果报错信息是英文看不懂，怎么办？"（看关键词：name / syntax / indent）

---

#### Step 3：完善算法——"从'能用'到'好用'"（约5分钟）

**教师活动**：
1. 过渡："Bug修完了，程序能跑对结果了——但这就够了吗？"
2. 出示情景："我把代码里的35改成30，94改成80，运行——什么结果都没有！"
3. 学生反应：沉默、困惑、"程序坏了？"
4. 引导分析："不是程序坏了，是这道题无解（30头80脚不存在整数解）。但程序什么都不说，用户会以为程序坏了。"
5. 引入"变量跟踪法"（PPT展示）：
   - 新增一个变量`jie`，初始值为0（表示"还没找到解"）
   - 如果找到了解（if条件成立），把`jie`改成1
   - 循环结束后，检查`jie`：
     - 如果`jie == 1`：已经输出过解了，正常结束
     - 如果`jie == 0`：说明循环跑完了都没找到解，输出"此题无解"

   完善后的代码结构（PPT展示）：
   ```python
   jie = 0          # 新增：记录是否有解
   ji = 0
   while ji <= 35:
       tu = 35 - ji
       if 2*ji + 4*tu == 94:
           print("鸡:", ji, "只")
           print("兔:", tu, "只")
           jie = 1   # 找到了，标记为有解
       ji = ji + 1
   
   if jie == 0:     # 循环结束后检查
       print("此题无解")  # 新增：无解提示
   ```

6. 运行验证：先跑35头94脚（有解），再跑30头80脚（无解），观察两种结果。
7. 追问："好的算法应该解决'一类问题'，而不是'一个问题'。如果要让程序能解任意头数和脚数，怎么办？"
8. 引入`input()`（PPT展示）：
   ```python
   tou = int(input("请输入总头数："))
   jiao = int(input("请输入总脚数："))
   ```
   "把固定的35和94，变成用户输入的`tou`和`jiao`——程序从此万能！"

**学生活动**：
- 在自己的代码上添加`jie`变量和`if jie == 0`判断
- 测试有解和无解两种情况
- 尝试将固定数字改为`input()`输入（选做，教师提供半成品代码）

**关键提问**：
- "为什么用jie=0和jie=1，而不是直接用'有解'和'无解'这两个词？"
- "如果去掉`if jie == 0`这部分，程序有什么缺陷？"
- "从'固定数字'到'用户输入'，程序发生了什么变化？"

### 环节三：探究活动——"三关挑战：运行→调试→完善"（约12分钟）

**环节目的**：将环节二学到的三阶段方法应用到具体任务中，从模仿到创造。

---

#### 探究一：Bug猎人——调试三个程序（约4分钟）

**任务内容**：
教师提供三个带有不同bug的鸡兔同笼程序（与环节二的三个bug对应但数据不同），学生分组运行、读报错、定位、修正。

**Bug程序A（大小写）**：变量`Ji`和`ji`混用
**Bug程序B（中文标点）**：用了中文冒号或中文括号
**Bug程序C（缩进）**：`while`或`if`后面的代码没有缩进

**操作要求**：
- 每个小组选择1个Bug程序（或按A-B-C轮换）
- 记录：报错类型 → 报错行号 → 错误原因 → 修正方法 → 运行验证
- 完成后举手，教师抽检

**教师活动**：
- 巡回指导，重点关注报错时学生的第一反应（是慌张还是冷静读报错）
- 对读完报错就定位成功的学生，请其上台分享"你是怎么做到的"
- 对反复修改仍报错的学生，引导其对照"四错清单"逐一排查

**预设问题及应对**：
- 学生改了大小写但还报错 → 检查是否还有别的地方也混用了
- 中文标点改不过来 → 提示切换输入法到英文状态，关闭中文输入法
- 缩进改了但报错行号变了 → 说明缩进改对了，但下面还有别的缩进错误，继续往下找

---

#### 探究二：算法完善——让程序能判断"无解"（约4分钟）

**任务内容**：
修改自己的鸡兔同笼代码，添加`jie`变量跟踪是否有解，并测试以下两种情况：
- 情况1：35头94脚（有解）→ 应输出"鸡:23只 兔:12只"
- 情况2：30头80脚（无解）→ 应输出"此题无解"

**操作要求**：
- 在代码开头添加`jie = 0`
- 在`if`条件成立处添加`jie = 1`
- 在循环结束后添加`if jie == 0: print("此题无解")`
- 分别测试两种情况，截图或记录结果

**教师活动**：
- 对完成快的学生，追问："如果同时有多个解（比如特殊情况），jie=1还够吗？"（引导思考多解问题）
- 对完成慢的学生，提供"填空版"半成品代码：
  ```python
  jie = ___  # 填0
  ji = 0
  while ji <= 35:
      tu = 35 - ji
      if 2*ji + 4*tu == 94:
          print("鸡:", ji, "只")
          print("兔:", tu, "只")
          jie = ___  # 填1
      ji = ji + 1
  
  if jie == ___:  # 填0
      print("此题无解")
  ```

**教师活动**：

## 六、公开课特别备忘

| 备忘项 | 具体说明 |
|--------|----------|
| **教材一致性** | 本课内容与教材第19-20页完全对应：运行程序（Open→Run Module）、调试程序（四错清单）、完善算法（jie变量+input）。教材中"试一试""练一练"均融入探究活动。 |
| **学生动手频率** | 全课学生操作IDLE时间≥10分钟（运行、调试、修改）。探究一三人小组分工调试，探究二独立修改代码，探究三选做通用化。 |
| **信息科技味** | 本课聚焦"工程化思维"——写代码只是第一步，运行调试完善才是完整过程。Python报错信息、IDLE操作、input()函数都是本课独有的IT内容。 |
| **差异化教学** | 探究一提供三种不同Bug（难度相近）；探究二提供半成品填空代码；探究三为选做，降低入门门槛。 |
| **时间控制** | 35分钟紧凑安排：调试环节（5分钟）是核心，必须让学生充分体验"找bug→修bug→验证"的完整闭环。若时间紧张，探究三可作为课后作业。 |
| **薄弱学生支持** | 提供"四错清单"卡片（可打印发给学生）；提供半成品填空代码；小组调试时让能力强的学生带能力弱的学生；教师巡回时优先帮助中英文输入法切换困难的学生。 |
| **设备检查** | 课前确保：① IDLE已安装且能正常运行；② 学生机上有三个Bug程序文件（教师提前分发到素材文件夹）；③ 学生第4课的鸡兔同笼代码已保存且可打开。 |

---

> **核心教学理念**：程序员的成长不是从"写出完美代码"开始的，而是从"写出有bug的代码，然后亲手把bug找出来并修掉"开始的。调试不是失败，而是学习。本课让学生在"出错→修错→成功"的循环中，建立程序工程化的底层自信。
