一、这套卷子怎么用（先看这里）诊断逻辑与批改流程

命题意图：不是排名，而是定位困难点。全卷 25 个作答点，每一题都对应教材第一单元的一个具体知识点 + 一种常见误区；干扰项全部来自学生真实易错处（= 与 ==、枚举边界、变量语义、报错类型、AI 生成代码照单全收等），因此错在哪一题、错成哪个选项，本身就是诊断信息。
  1. 批改时额外记录两件事：①每道题的错误选项/错误写法；②学生在题号旁画的"?"标记。
  2. 按知识域统计得分率（用第五部分的空白表），而不是只看总分。总分相近的两个学生，薄弱点可能完全不同。
  3. 用"?"标记区分四类学生状态：
    作答 × 标记说明处理建议
    答错 + 未标 ?隐性误区：以为自己会，实为概念性错误最危险，全班优先讲评，需纠正错误概念
    答错 + 标 ?自知不会，知识有缺口小组/个别补救，补完用变式题复测
    答对 + 标 ?靠猜测或记忆不牢，属"假性掌握"换情境再测一题，确认真会
    答对 + 未标 ?已掌握可安排为同伴讲解员
  4. 记录未完成题号：30 分钟做不完，若集中在第 16、17、19 题，通常说明"读代码速度慢"，也是 D 域（Python 语法与程序阅读）的薄弱信号。

薄弱判定阈值：某知识域得分率 ≥85% 为"已掌握"；60%～84% 为"基本掌握、需巩固"；＜60% 判为薄弱，优先补救。多选题另看错因类型：漏选集中＝概念边界模糊（知道一半）；错选集中＝概念性错误或凭感觉作答。

1A选 B（先写程序）、选 A/D（顺序乱）把"写代码"当成解题第一步，缺少问题分析意识；不理解四步流程用投票情境做四步卡片排序：问题分析 → 抽象建模 → 设计算法 → 验证优化

5C选 A（兔最多 36 只）、选 D（35 次）循环边界与枚举范围对不上，典型 off-by-one列表写出 tu = 0,1,…,35,36 时循环是否执行，直观看到"取 0～35 共 36 种"
6A选 D、选 B未建立枚举法两要素：范围 + 正确解判断条件用"算 24 点""摘录好词好句"举例，让学生自己说出范围与条件
7D选 A（写成 =），或选 C（<>）把数学等号迁移到 Python；赋值号与比较运算符混淆（本单元最高频错误）并排对比 a = a + 1（赋值）与 if ... == 94:（判断），上机各写一行看报错
8D选 C、D 或空答不知道 input() 返回字符串、需 int() 转整型IDLE 中输入字符串与数字比较，亲历报错；再补上 int() 观察变化
9E选 B/D（把 NameError 当语法错误）读不懂报错信息，无法把报错定位到大小写/变量名"报错信息—错误类型—修改方法"三列配对练习（教材 p20–21 三个例子）
10F选 B（照单全收）、选 C（只测一次）对 AI 生成代码缺乏核验意识；不会设计覆盖分支的测试数据发一段"AI 生成但有错"的猜数字代码让学生找茬，并列出三组测试数据
11D漏选 D、错选 C语法规范知识碎片化；大小写敏感未建立；不理解注释不执行做一张"Python 书写规范检查清单"（半角标点 / 冒号 / 缩进 / 大小写 / # 注释），上机逐项自查
12C错选 A（范围从 1 开始）、错选 D（找到解就停）枚举边界遗漏 0；不理解教材算法会继续枚举到范围结束把教材 p12 表格的 35 / 12 / 0 三列补完整，讨论"兔 0 只"是否可能被漏掉
13E错选 B（认为不报错＝正确）缺少"逻辑错误"概念，误把能运行等同于结果正确给一个能正常运行但条件写错、结果不对的程序，让学生找逻辑错误
14B错选 C、D人机交互三环节不清；循环终止条件（cai = da 时结束）搞反按"输入 cai — 数据比较 — 输出提示"三栏重画教材 p26 模型表，再对照 p27 流程图
15F错选 A、漏选 B 或 D不知道"算法必须有输出"；缺少无解处理与多分支验证意识把总脚数改成无解的数据运行，观察"什么都不输出"的问题，再加 jie 变量与提示
16D（1）答成票数；（2）填 1001；（3）答"票数变多/结果错"读代码能力弱；不知道循环变量更新（i = i + 1）决定循环能否结束逐行标注变量含义，手工跟踪前 3 次循环；删掉 i = i + 1 上机观察死循环
17C（1）填 35；（2）填 =；（3）填 1 或 tu代码补全不精确；边界与比较符双重失分；不会写递增对照教材 p16 完整代码逐行订正，运行确认输出"23 只鸡，12 只兔"
18E情况二答"逻辑错误"；两空都答"语法错误"三类错误（录入 / 语法 / 逻辑）分类不清各举一例上机复现：Tu、漏冒号、条件写错，记录三者的报错差异

六、按薄弱域讲评与补救讲评顺序建议：先 C、D，再 E、B，最后 A、F

若薄弱域典型表现一节课内可做的补救动作
A / B审题后直接写代码；说不清变量代表什么；把已知数当关键要素暂停写代码，回到"问题分析 → 抽象建模"：用卡片/表格把对象、数量、关系摆出来，先口头说清算法，再动笔
C循环边界总差 1；判断条件写反；流程图与代码对不上用"手工跟踪表"逐轮记录变量值（tu、ji、总脚数），把流程图每一步对应到代码行；先读后写
D=/== 混用、漏冒号与缩进、字符串直接比大小、看不懂代码不靠背语法：发"规范检查清单"＋一段埋了 5 处错的代码，上机逐一订正到能运行，形成肌肉记忆
E见到报错就举手等答案；认为不报错就对了教师故意埋三类错误，让学生根据报错信息填"错误类型—位置—改法"三列表
FAI 给什么就交什么；只测一次就下结论讲清提示词三要素（明确程序设计语言 / 清晰描述算法 / 说明验证要求），并要求每组提交"偏大、偏小、相等、无解"四类测试用例
复测建议：讲评后 3～5 天，用同一知识点换情境出 5 题小测（如把"投票"换成"统计班级图书借阅"、把"鸡兔同笼"换成"百钱买百鸡"、把"猜数字"目标数改成 1～50），重点看原先"答错且未标 ?"的学生是否真正转变。若 C、D 两域仍低于 60%，说明需要先补"读代码"而不是继续加新题。
